Part 7Orchestrator & tools

The orchestrator is a thin agent runtime. It registers tools, calls tools, runs goals through a planner, and exposes traces and metrics. No LLM is required on the default path.

Summaries are derived: fidelity=…, 00/11 counts, ready=… score=…, or first keys. Traces reset at the start of each run_goal.

7.2 Planner rules

plan_from_goal normalises whitespace/case and matches keywords:

INTENT KEYWORDSTOOL PLAN
bring, calibrat, ready, tunecalibrate_qubit(qubit_id parsed 0|1, target 0.88 or 0.92 if high/strict)
bell, circuit, entangl, pairrun_bell_pair(shots 1024|256 few/quick|4096 many/precise)
state, health, status, ready?, temperatureget_device_state
cancel …cancel_job(job_id token)
default (no match)get_device_state then calibrate_qubit(0, 0.85)

Table 7.2. Deterministic planner mapping (planner.py).

plan() tries maybe_llm_plan first when CONDUCTOR_ENABLE_LLM is truthy and openai imports; otherwise plan_from_goal. LLM failures return None and fall through. The API’s POST /goals uses Orchestrator.run_goal, which imports plan_from_goal as its default planner function (note: the server also imports plan but run_goal defaults to plan_from_goal unless a planner callable is passed).

7.3 Early stop

If a step’s tool is calibrate_qubit or run_bell_pair and ok is False, run_goal breaks the plan early. Visibility tools do not abort the sequence.

7.4 Metrics surface from orchestrator

get_metrics() returns calibration metrics dict, per-tool call counts and avg latency, optional adapter get_stats() (total_jobs, total_shots on the sim), and an interface_latency_p50_hint aliased from avg interface latency.

Sources. orchestrator/orchestrator.py; orchestrator/planner.py

8.1 Layout rules

  • Full-viewport black shell (h-screen w-screen).
  • Toolbar without traffic lights: brand, LIVE badge, READY centered, ⌘K and refresh on the right.
  • Three-pane stage at rest. Left: high-contrast drift grid, coplanar with the fidelity surface. Center: Device3D (qubits, chiplets, resonators, readout card). Right: isometric cryostat plate with status strip.
  • Two iPadOS Split View–style separators. Hover shows a capsule drag handle. Drag to resize. Each pane keeps a minimum width.
  • No glass inset. No tabs. (PR #2 labels drift | device were tabs. That control is gone.)
  • Bottom-right StageStateChip (OFFLINE → DRIFT → CALIBRATING → RUNNING → READY / FAILED).
  • Content area: stage absolute inset-0; dock overlaid at bottom over a Safari-safe bottom-third frost (.stage-blur, no backdrop-filter) so the canvases extend underneath and the top two-thirds stay sharp.
  • Composer max width ~42rem, centered; six workflow chips above it.
  • Dock transcript uses you (right) / agent (left) bubbles above chips, with small tool pills under agent replies. No card wall on first paint.

8.2 Drift visualisation

calibration-surface.tsx builds a PlaneGeometry heightfield from estimateFidelity(dx,dy,base), peaked at the true offset implied by live detuning. Cyan marker = true; amber = applied at origin of the applied frame. Colours: ≥0.88 blue, ≥0.75 orange, else gray. On current main the left grid is high contrast and shares the tilted group with that surface, so the grid and the mountain sit coplanar. WebGPU via async three/webgpu renderer when navigator.gpu exists; else WebGL + banner.

8.3 Composer, chips, ledger, details

Workflow chips: Calibrate Q0, Bell pair, Q0 readiness, Device status, Improve Bell, Diagnose Q0 — each submits a goal string through api.postGoal. Turns append to local state with status running→succeeded/failed, traces, fidelityHistory, bellCounts. The dock transcript stacks you/agent bubbles above chips; selecting a turn expands details (fidelity climb, tool traces, optional counts). The primary operator path stays first-class: a natural-language goal or a chip, then calibrate, then READY, then a Bell circuit.

8.4 Command palette and demos

⌘K opens cmdk actions: goals, refresh, force fail next calibration, start long job. Demo actions hit /demo/* endpoints. Cancel uses goal cancel {jobId} or stop button on running jobs.

8.5 Polling

Device + metrics refresh every 6.5 s when connected. Active running jobs poll every 850 ms; SSE also attaches via EventSource to /sse/jobs/{id}.

  1. Click Bell pair.
