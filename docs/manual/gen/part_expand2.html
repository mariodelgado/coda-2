Part 3BArchitecture decision records

Short ADRs for this system. Each records context, decision, and consequences as shipped on main.

ADR-001 — Narrow adapter waist

Context. Real QPUs differ wildly in pulse programming models. Decision. Six synchronous methods on QPUAdapter. Consequences. Orchestrator/UI stay stable; week-1 work is implementing the six methods. Async/hardware batching is a future wrapper concern.

ADR-002 — Deterministic planner by default

Context. NL goals are convenient; LLM keys are not. Decision. Rule-based planner; optional LLM behind env flag. Consequences. Demo and CI are offline; goal coverage is intentionally small; expand rules or enable LLM later without changing tools.

ADR-003 — In-memory everything

Context. Weekend prototype. Decision. No database. Consequences. Refresh-safe only within process lifetime; persistence is an explicit next step.

ADR-004 — Instrument UI over dashboard cards

Context. Early Streamlit UI became a card wall. Decision. Replace with a Next.js instrument (65/35 at first; now a three-pane stage over a dock). Consequences. Higher front-end complexity; clearer founder narrative; WebGPU dependency with WebGL fallback.

ADR-005 — Expose sim detuning

Context. Calibration needs a visible problem. Decision. get_detuning on sim; stage markers. Consequences. Teaching oracle; stub must raise; production must replace with measured diagnostics.

ADR-006 — Domain failures as 200 + flags

Context. Agents should parse tool outcomes. Decision. Calibration failure returns HTTP 200 with success/ok false. Consequences. Do not key off HTTP status alone for domain errors; UUID errors still 4xx.

Part 10COperator runbook (90 seconds)

Compressed runbook matching the README’s 2-minute founder demo, expanded with failure checks.

  1. Boot. make setup once. Then make run-api and make run-ui-dev.
  2. Verify LIVE. Toolbar badge green; if red banner, API is down.
  3. Watch drift. Cyan vs amber; Δf readout moves slowly.
  4. Calibrate Q0. Expect climb HUD; ledger turn; threshold toast if crossed.
  5. Inspect traces. Open ledger row — tool names must be real (calibrate_qubit), not prose.
  6. Bell pair. Counts appear; stage remains primary.
  7. Q0 readiness / Device status / Diagnose Q0. get_device_state fills fidelity/readiness when Bell alone is not enough.
  8. Improve Bell. Precise (more shots) Bell after calibrate.
  9. Fail path. ⌘K force fail; recalibrate; confirm success=false behaviour.
  10. Cancel path. Start long job; stop; confirm CANCELLED.
  11. Metrics. Refresh; confirm attempts/successes moved.
  12. Stub sanity (optional). Restart API with CONDUCTOR_QPU_BACKEND=stub; confirm never-ready and circuit failure messaging.

Part 2CTheory — observability as a trust protocol

Extends Part 2: why traces + metrics + drift form a protocol, not a dashboard aesthetic.

2C.1 Three audiences, one ledger

A founder watching the demo needs to see that calibration costs time and sometimes fails. An operator needs to see whether the device is ready and what the last tool did. An agent needs machine-readable ToolResults and stable tool names. The ToolTrace buffer and /traces endpoint serve all three if the UI does not invent a parallel narrative channel.

2C.2 What would falsify the design

  • Calibration “success” without a fidelity history that crossed the threshold.
  • UI READY state disagreeing with /device/state.is_ready for the same poll.
  • Traces that do not match tools actually invoked (LLM fiction).
  • Interface latency that never samples because applies are skipped.
  • A hardware port that requires rewriting page.tsx to show drift.
Rule of thumb If swapping the adapter requires redesigning the ledger, the waist was too wide. If swapping the planner requires redesigning metrics, the metrics were tied to NL rather than to tools.

Part 6CMetrics algebra

Formal-ish definitions matching CalibrationMetrics and MetricsAggregator.

calibration_success_rate = successes / attempts          # 0 if attempts=0
avg_time_to_calibrated   = total_time_to_cal_s / successes  # 0 if successes=0
avg_interface_latency    = total_interface_latency_s / latency_samples

aggregator.p50_ms = percentile_50(latencies_ms)
aggregator.p95_ms = percentile_95(latencies_ms)
aggregator.avg_fidelity = mean(fidelity_samples)

Note: orchestrator records tool latencies separately from calibration interface latency. /metrics returns both. UI may emphasise calibration block for the founder narrative.
