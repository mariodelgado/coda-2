Front matterWho this is for

Coda 2 is a three-pane instrument for a quantum processing unit: parameter-drift landscape on the left, the 3D device in the center, the cryostat plate on the right, and a chat dock across the bottom. It is a control plane, and it is a stage. Three roles use one instrument. They do not do the same job.

Beyond a chat window

A normal ChatGPT element is a transcript. You type, a model replies, and any physics lives only in sentences that scroll away. Coda 2 is instrument-first. The first thing you learn is the stage: drift on the left, the device in the center, the cryostat on the right. Language is one channel, not the only surface. Physics stays in view while you talk. The chips in the dock are one-click goals.

  • Visual — the three panes: left drift landscape, center 3D device with the readout card, right cryostat plate.
  • Text — natural-language goals and the agent transcript in the dock.
  • Math — fidelity, Δf, T1 / T2, ToolTraces, and the metrics.

Table A.1. Who uses Coda 2. Pick your row. The later parts go deeper for that role.

Quantum control engineer

You build and maintain the control software. A goal enters as POST /goals. The agent maps the goal to a tool. Every tool call writes a ToolTrace.

You keep the QPUAdapter seam. The waist is six methods: submit_job, poll_job, cancel_job, get_device_state, get_calibration, apply_calibration_update. The calibration loop measures fidelity, decides, applies an update, and measures again. The three metrics are time-to-calibrated, calibration success rate, and interface latency.

The default path is offline. It does not need a language-model key. If an optional planner is on, it falls back to the same rules. You extend the tools, or you replace the adapter. You keep the seam.

QPU operator

You run the instrument. You calibrate, check readiness, run circuits, and cancel jobs. You land on the idle home. The toolbar shows LIVE when the UI is connected. It shows READY centered when the device is fit for a circuit. You send a goal with a chip, or you type in the composer. Recalibrate when the state chip falls back to DRIFT, or when Δf grows. High Δf means the controls are off-target.

Read fidelity as Q0 percent in the toolbar and on the readout card in the center pane. Read the left pane for drift (orange applied versus blue true). Read the right pane for the cryostat plate and the status strip under it. The state chip sits at the far right.

Technical lead

You evaluate Coda 2 for your stack. You are a technical lead or a buyer of the integration. You use the same product the operator uses. You do not run a separate trial.

You follow one path: calibrate qubit 0, see READY, then run a Bell pair. You read the three metrics. You read the adapter seam. A simulator stands in for the device until a hardware adapter is connected. Your driver replaces that simulator behind the same six methods.

Not for This manual is not a cryogenics handbook. The millikelvin figure is computed from fidelity on the simulator. It is not a fridge sensor. The right-hand plate is an isometric drawing, not a fridge readout. Coda 2 is not an open chat for science or finance. The planner accepts four goal families. If a sentence matches no keyword, the planner checks device state, then it runs a soft calibrate. That is the catalog.

What success means here. READY on the toolbar matches device.is_ready. Fidelity is up. Δf is smaller than it was at idle. You can try a circuit next. The full step-by-step, with every number named, is the Instrument walkthrough (STE.3).

Task 2 — Run a circuit (Bell)

Prefer READY first. Click the Bell pair chip, or type a goal that says Bell, circuit, or pair. The planner calls run_bell_pair. Success looks like this: the agent reply reports an estimated Bell fidelity — about 0.42 on this seed. The transcript now carries two turns, and a small tool pill marks the run.

FIG. A.6Circuit done. The transcript has a second turn: you ask for a Bell pair and report fidelity; the agent answers with the estimate and a run_bell_pair tool pill. All three panes remain visible: drift left, device center, cryostat right.

Task 3 — Check device state

Type device state, or a health, status, or temperature word. The planner calls get_device_state. Success looks like this: you can read LIVE, READY, fidelity, and Δf. You do not start a calibration, and you do not start a circuit. Use the idle home (FIG. A.3) before a goal. Use the map (FIG. A.7) after a session. There is no separate status still.

Task 4 — Cancel a job

Type cancel and the job id. The planner calls cancel_job. Success looks like this: that job stops. The session stays open. This book has no cancel still. FIG. A.2, card 04, is the picture for this task.

Front matterOverview

Coda 2 takes a goal in ordinary language and runs it on a quantum processing unit through a typed tool catalog and a QPU adapter. The interaction is meant to go beyond a normal ChatGPT element.

You see and manipulate properties of a quantum computer in the format that fits the moment. Visual: a three-pane stage — drift landscape on the left, the 3D device in the center, the cryostat plate on the right. Text: natural-language goals and the agent transcript. Math: fidelity, Δf, T1 / T2, ToolTraces, and metrics. The product is instrument-first. Physics stays in view. Language is one channel, not the only surface. A chat-only UI would bury those properties in prose and scroll them away.

An operator states a goal. An agent maps that goal onto a small catalog of typed tools. The tools call the adapter. The screen is an instrument: a live three-pane stage (drift · device · cryostat), and a dock that holds the conversation.

A simulator stands in for the device until a hardware adapter is connected.

Day to day the product does four jobs: bring a qubit to ready, run a Bell pair, check device state, and cancel a job. The control plane records time-to-calibrated, calibration success rate, and interface latency. The adapter seam is six methods. The default path is offline and does not need a language-model key. When the optional planner is on, it falls back to the same rules.

Use this section when you operate the app. The screenshots below are a complete user flow captured on main (three-pane chrome) with the API on :8000, the UI on :3000, and the live narrator writing each agent reply (NVIDIA NIM when keyed, otherwise a template). Dock layout (conversation shape)

The stage is three panes with two splitters between them. The dock sits at the bottom, over a bottom-third frost. Read the bottom of every screenshot top-to-bottom:

  1. Chat transcript — scrollable turns. Each turn has a you line (the goal) and an agent line (plain-English narration from agent_message). Tiny tool pills may sit under the reply; they are secondary.
  2. Chips — Calibrate Q0 · Bell pair · Q0 readiness · Device status · Improve Bell · Diagnose Q0 (one-click goals).
  3. Composer — type a goal and send (or ⌘K). Lowest control in the dock.

The three-pane stage extends under this dock. Panes start roughly equal. Left: high-contrast drift grid, coplanar with the fidelity surface. Center: the 3D device — qubit spheres Q0 and Q1, chiplets, resonators — plus a readout card at top right (Q0 / Q1 fidelity, T1, T2, err, mK). Right: an isometric dilution-refrigerator plate labelled FIG 1 · DILUTION FRIDGE, with a status strip under it (READY · Q0 % · mK · Δf) and a StageStateChip at the far right (DRIFT · CALIBRATING · READY…). Two iPadOS Split View–style splitters separate the three panes. Hover shows a capsule drag handle. Drag to resize. Each pane keeps a minimum width, roughly 22–28% of the stage. There are no traffic lights, no glass inset, and no tabs. A Safari-safe bottom-third progressive frost (stacked solid translucent bands on a dedicated .stage-blur sibling — no backdrop-filter on the dock) softens only the lower third so the viz stays readable under the transcript without frosting the whole stage.

What is real vs simulated

Honesty The control plane (adapter contract, orchestrator, traces, FastAPI, Next.js UI, metrics) is real software. The device is a NoisySimulatorBackend: a toy 1–2 qubit model with a hidden true parameter vector, random-walk and sinusoidal drift, and a monotonic-but-noisy fidelity function of ‖applied − true‖. Bell counts are a cheap stochastic simulation. There is no dilution refrigerator. There is no AWG. There is no pulse compiler. A ConductorShapedAdapter stub documents the shape of a real driver and refuses real work.
